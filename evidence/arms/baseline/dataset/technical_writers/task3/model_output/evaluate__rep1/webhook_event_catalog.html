TaskFlow API — Webhook Event Catalog

This catalog lists every webhook event the TaskFlow platform emits, combining two sources: the events declared as subscribable values in the OpenAPI 3.0 specification (taskflow_openapi_v2_extract.yaml, API version 2.0.1) and the events actually observed in a production delivery log (webhook_delivery_log.json, export dated 2024-03-10).

Sources reconciled: OpenAPI spec (declares 10 event values) · Production delivery log for webhook 301 → https://integrations.acme.corp/taskflow/events (12 deliveries, 12 unique event types, 11 successful / 1 failed).

task.due_date_approaching

Production only
Description
Fired when a task's due date is approaching. The payload carries the due date and the number of days remaining. Both scheduled events in the sample fired at exactly 00:00:00Z, consistent with a once-daily scheduled job.
Trigger
Scheduled daily check; fired while the task's due date is still in the future within the reminder window (observed at days_remaining: 9).

  "event": "task.due_date_approaching",
  "task_id": 1042,
  "due_date": "2024-03-15T00:00:00Z",
  "days_remaining": 9
}

Observed in production: delivery d-90007, 2024-03-06T00:00:00Z, HTTP 200.

Subscribing to events

Register a webhook with POST /webhooks. The request requires a url and an events array whose values must come from the ten spec-declared event names listed above. An optional secret enables HMAC payload verification, and active (default true) controls whether the subscription is live. A successful registration returns 201 Created. Delete a subscription with DELETE /webhooks/{webhookId}, which returns 204 No Content.

Undocumented events cannot be subscribed to. task.due_date_approaching and task.overdue are emitted by the platform but are not part of the events enum in the specification, so they cannot be requested at registration time. Existing endpoints observed receiving them (such as webhook 301 in the sample) appear to receive all events regardless of subscription. If your integration depends on these events, verify actual delivery behavior against your own endpoint and track the spec update in the discrepancy report before relying on them.

Delivery and retry semantics

TaskFlow delivers events by HTTP POST to the destination URL registered for the webhook. A delivery is considered successful when the endpoint responds with an HTTP 2xx status. When the endpoint returns an error response, TaskFlow retries the delivery — the production sample shows 3 retry attempts for the failed project.deleted delivery (d-90008, destination returned 502) — and if all attempts fail, the delivery is marked final_status: "failed" and is not re-attempted further.

Recommendations for consumer endpoints:

  • Respond quickly with 2xx and process the payload asynchronously; slow handlers risk timeouts.
  • Treat event delivery as at-least-once: deduplicate using task_id/project_id plus the event type and timestamp.
  • Do not rely on ordering between events; in the sample, related events (task.updated and task.assigned) can both fire for one user action.
  • Monitor for missed project.deleted-style events by periodically reconciling state, since permanently failed deliveries are not re-sent.

Verifying payloads (HMAC)

When a webhook is registered with a secret, TaskFlow signs each payload with that shared secret using HMAC. Verify the signature server-side before trusting the payload contents. Keep the secret out of client-side code and rotate it by re-registering the webhook with a new secret value.

Known gaps

  • Spec gap: task.due_date_approaching and task.overdue are emitted in production but absent from the events enum. File them for addition to the specification.
  • Docs gap: the legacy v1 documentation advertised only 4 events (task.created, task.updated, task.deleted, project.created). The current catalog supersedes that list entirely.
  • Payload fidelity: the production log stores payload_excerpt values. Example payloads in this catalog are reconstructed from those excerpts and may omit fields present in real deliveries.
