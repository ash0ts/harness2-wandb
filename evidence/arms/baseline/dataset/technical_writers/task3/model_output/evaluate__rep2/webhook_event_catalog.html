Delivery guarantees

Failed deliveries are retried up to 3 times; if every attempt fails, the delivery is marked failed. Evidence: delivery d-90008 (project.deleted) returned HTTP 502 with retry_attempts: 3 and final_status: "failed" in the March 2024 export. The exact backoff interval is not specified in either source and is pending engineering confirmation.

Payload authenticity: supply a secret when creating a webhook and verify the HMAC signature computed over the raw request body on each delivery.

Event catalog

Task events

task.createdDeclared + observed

Description
Fires when a new task is created in any project your webhook can access.
Trigger condition
A POST /tasks request succeeds (201 Created), or a task is created through the TaskFlow UI or a project template.
Example payload
{
  "event": "task.created",
  "timestamp": "2024-03-01T14:22:00Z",
  "webhook_id": 301,
  "data": {
    "task_id": 1042,
    "project_id": 12,
    "actor_id": 57
  }
}
Reconstructed from delivery d-90001 (HTTP 200)

task.updatedDeclared + observed

Description
Fires when one or more fields of an existing task change.
Trigger condition
A PUT /tasks/{taskId} request succeeds, or an equivalent change is made in the UI. The payload lists exactly which fields changed via changed_fields.
Example payload
{
  "event": "task.updated",
  "timestamp": "2024-03-01T15:05:33Z",
  "webhook_id": 301,
  "data": {
    "task_id": 1042,
    "changed_fields": ["status", "assignee_id"],
    "actor_id": 57
  }
}
Reconstructed from delivery d-90002 (HTTP 200)

task.assignedDeclared + observed

Description
Fires when a task is assigned to an assignee, including reassignment to a different assignee.
Trigger condition
A POST /tasks/{taskId}/assign request succeeds, or assignee_id is set via task update. Fires on the new assignment regardless of the notify flag (which controls email notification only).
Example payload
{
  "event": "task.assigned",
  "timestamp": "2024-03-05T10:02:00Z",
  "webhook_id": 301,
  "data": {
    "task_id": 1050,
    "assignee_id": 93,
    "actor_id": 57
  }
}
Reconstructed from delivery d-90006 (HTTP 200)

task.deletedDeclared + observed

Description
Fires when a task is permanently deleted. Delivered after the deletion, so the referenced task no longer exists.
Trigger condition
A DELETE /tasks/{taskId} request succeeds (204), or the containing project is deleted with cascade=true.
Example payload
{
  "event": "task.deleted",
  "timestamp": "2024-03-08T09:00:00Z",
  "webhook_id": 301,
  "data": {
    "task_id": 999,
    "project_id": 3,
    "actor_id": 57
  }
}
Reconstructed from delivery d-90010 (HTTP 200)

task.due_date_approachingObserved only

Description
Scheduled reminder that a task's due date is approaching. Not declared in the OpenAPI spec; not subscribable via POST /webhooks as specified.
Trigger condition
Daily scheduled check. Production evidence: fired at exactly 00:00:00Z with days_remaining: 9, indicating a nightly job that fires when the task is within a fixed window of its due date.
Example payload
{
  "event": "task.due_date_approaching",
  "timestamp": "2024-03-06T00:00:00Z",
  "webhook_id": 301,
  "data": {
    "task_id": 1042,
    "due_date": "2024-03-15T00:00:00Z",
    "days_remaining": 9
  }
}
Delivery d-90007 (HTTP 200)

task.overdueObserved only

Description
Scheduled notification that a task is past its due date. Not declared in the OpenAPI spec; not subscribable via POST /webhooks as specified.
Trigger condition
Daily scheduled check after midnight UTC once the due date has passed. Production evidence: fired at 00:00:00Z with days_overdue: 1.
Example payload
{
  "event": "task.overdue",
  "timestamp": "2024-03-16T00:00:00Z",
  "webhook_id": 301,
  "data": {
    "task_id": 1042,
    "due_date": "2024-03-15T00:00:00Z",
    "days_overdue": 1
  }
}
Delivery d-90011 (HTTP 200)

project.deletedDeclared + observed

Description
Fires when a project is permanently deleted. With the default cascade=true, every task in the project is also deleted (each generating its own task.deleted event).
Trigger condition
A DELETE /projects/{projectId} request succeeds (204).
Example payload
{
  "event": "project.deleted",
  "timestamp": "2024-03-07T08:20:00Z",
  "webhook_id": 301,
  "data": {
    "project_id": 3,
    "actor_id": 57
  }
}
Delivery d-90008 — failed after 3 retries (HTTP 502, final_status: failed)

member.removedDeclared + observed

Description
Fires when a user's membership on a project is removed.
Trigger condition
A membership is revoked on a project (UI or API). Task assignments held by the removed member are not automatically reassigned.
Example payload

  "event": "member.removed",
  "timestamp": "2024-03-07T14:10:00Z",
  "webhook_id": 301,
  "data": {
    "project_id": 12,
    "user_id": 45,
    "actor_id": 57
  }
}
Reconstructed from delivery d-90009 (HTTP 200)

Observations from the delivery log

  • 12 deliveries, 11 successful, 1 failed (project.deleted, HTTP 502, exhausted 3 retries).
  • All payload excerpts carry actor_id — the user who caused the event — except the two scheduled events (task.due_date_approaching, task.overdue), which are system-generated and have no actor.
  • Scheduled events fire at exactly 00:00:00Z, consistent with a nightly batch job.
